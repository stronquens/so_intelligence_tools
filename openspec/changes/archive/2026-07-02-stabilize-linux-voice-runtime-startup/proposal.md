## Why

After a reboot, Linux voice features currently depend on manual recovery: the Whisper and Piper Docker services may not be ready when the user session starts, Docker may point at an unavailable context, and newer Whisper images can enable an autogenerated API key. This breaks push-to-talk dictation and Codex voice output until the user runs repair commands.

## What Changes

- Add a Linux user service that ensures the local voice runtimes at login.
- Make the dictation listener order itself after that runtime service.
- Ensure the Whisper Docker env explicitly disables auth for the localhost-only service unless the user opts in.
- Add CLI install/start/status support for the voice runtime startup service.
- Document the boot behavior and recovery path for Linux.

## Capabilities

### New Capabilities

- None.

### Modified Capabilities

- `push-to-talk-dictation`: Linux dictation SHALL have its Whisper runtime ensured automatically at login and SHALL avoid unsupported autogenerated auth by default.
- `local-tts-voice-output`: Linux Codex voice output SHALL have its Piper runtime ensured automatically at login.
